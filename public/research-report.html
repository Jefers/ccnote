Research report

Future CCNote direction

A practical staged roadmap for growing CCNote from a mobile-first rota and client-card PWA into a dashboard CRM with calendar integration, messaging preferences, a backend, and a restricted Hermes agent.

← Back to CCNote Jump to next steps

Executive recommendation

Do not jump straight to a VPS-hosted AI CRM. The safest path is staged: keep the app useful locally, stabilise the data model, add backups, then introduce backend capabilities only when they unlock real value.

Local-first PWA
→ richer local CRM
→ export/import backups
→ backend/database/auth
→ iCal feed
→ Google Calendar sync
→ restricted Hermes agent
→ advanced automation

Recommended phases

1. Stronger local PWA

Keep GitHub Pages and local storage for now. Improve client profile structure, session editing, data migration, and JSON export/import.

2. Richer CRM

Add client detail screens, tags/statuses, contact preferences, health notes, progress notes, session history, and reminders.

3. Calendar foundation

Clean up the internal appointment/session model first, then add a private read-only iCal feed before Google OAuth.

4. Backend MVP

When the local model is stable, add authentication, a backend API, PostgreSQL, HTTPS, and backups.

5. Google Calendar

Add OAuth, event IDs, conflict detection, token encryption, and eventually two-way sync.

6. Hermes agent

Give a dedicated Hermes agent restricted API access, not direct root/server/database access.

Messaging integration

Start with deep links rather than full messaging APIs. This gives fast practical value without needing platform approvals or business-account APIs.

  • Phone: tel:+447700900000
  • SMS: sms:+447700900000
  • Email: mailto:client@example.com
  • WhatsApp: https://wa.me/447700900000
  • Telegram: https://t.me/username
  • Custom links for anything unsupported.

Each client should eventually have a preferred contact method, contact notes, best contact time, and consent/do-not-contact fields.

Calendar integration

Start with iCal export

A private read-only feed is simpler, works with Apple Calendar, Google Calendar, and Outlook, and avoids storing Google OAuth tokens at the start.

https://yourdomain.com/calendar/private-feed.ics

Add Google Calendar later

Google Calendar API should come after backend authentication exists. It unlocks event creation, conflict detection, reminders, and eventual two-way sync, but requires secure refresh-token storage and a Google Cloud OAuth setup.

Suggested future data model

  • Coach/User: name, email, timezone, business name, settings.
  • Client: first name, surname, phone, email, status, tags, notes.
  • Health profile: goals, injuries, medical cautions, limitations, training preferences, measurements.
  • Contact preferences: preferred method, WhatsApp/Telegram/social links, best contact time, consent notes.
  • Session/appointment: client, start/end, timezone, location, status, notes, recurrence, external calendar ID.
  • Notes/tasks: session notes, progress notes, reminders, follow-up tasks.
  • Calendar connection: provider, calendar ID, encrypted tokens, sync state.
  • Audit log: actor, action, entity, timestamp, metadata — essential once an agent can act.

VPS and backend architecture

A sensible future VPS layout is:

VPS
├── Caddy reverse proxy
├── frontend static app
├── backend API
├── PostgreSQL database
├── Hermes agent
└── backup service

Use Caddy for automatic HTTPS, Docker Compose for repeatable deployment, and PostgreSQL for structured CRM data. Before storing real client data, set up encrypted backups and test restore.

Dedicated Hermes agent

The agent should be useful but constrained. Recommended pattern:

Hermes Agent → restricted app API → database

Safe first capabilities:

  • Answer “who am I seeing today?”
  • Summarise client notes.
  • Find clients needing follow-up.
  • Draft WhatsApp/SMS/email messages.
  • Draft tasks and schedule changes for approval.

Avoid direct production shell access, unrestricted database writes, automatic message sending, or destructive actions without confirmation.
